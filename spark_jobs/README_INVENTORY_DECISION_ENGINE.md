# Inventory Decision Engine

A PySpark-based intelligent inventory management system that uses machine learning to predict demand and generate actionable reorder recommendations.

## Overview

This decision engine leverages a trained Random Forest regression model to:
- Predict product demand per store and product
- Calculate stock-out risk based on current inventory levels
- Generate smart reorder recommendations
- Provide actionable inventory management decisions

## Input Data

### 1. Demand Features (Parquet)
**Path:** `output/retail_aggregations`

Generated by the streaming aggregation job, contains:
- `store_id` - Store identifier (partition column)
- `product_id` - Product identifier (partition column)
- `total_units_sold` - Total units sold in time window
- `total_revenue` - Total revenue in time window
- `avg_units_per_minute` - Average units per minute
- `transaction_count` - Number of transactions

### 2. Current Inventory (CSV)
**Path:** `data/current_inventory.csv`

Contains current inventory snapshot:
- `store_id` - Store identifier
- `product_id` - Product identifier
- `current_stock` - Current stock level (units)
- `lead_time_days` - Supplier lead time (days)

### 3. Trained Model
**Path:** `models/demand_rf_model`

Trained Random Forest pipeline including:
- VectorAssembler (feature engineering)
- RandomForestRegressor (demand prediction)

## Decision Logic

### Demand Prediction
1. Load aggregated demand features from Parquet
2. Use trained Random Forest model to predict demand per 5-minute window
3. Convert to daily demand: `predicted_daily_demand = prediction × 288`
   - 288 = number of 5-minute windows per day (24 × 60 ÷ 5)

### Stock-Out Risk Calculation
```python
if current_stock < predicted_daily_demand × lead_time_days:
    risk = "HIGH"
elif current_stock < predicted_daily_demand × (lead_time_days + 1):
    risk = "MEDIUM"
else:
    risk = "LOW"
```

**Rationale:**
- **HIGH**: Stock won't cover demand during lead time → immediate stock-out risk
- **MEDIUM**: Stock barely covers lead time → buffer too thin
- **LOW**: Sufficient buffer beyond lead time → safe inventory level

### Reorder Quantity Calculation
```python
recommended_reorder_quantity = max(
    predicted_daily_demand × (lead_time_days + 2) - current_stock,
    0
)
```

**Rationale:**
- Target: `(lead_time_days + 2)` days of inventory
- Accounts for lead time + 2-day safety buffer
- Subtracts current stock to get net reorder need
- Never negative (minimum 0)

### Action Assignment
```python
if risk == "HIGH":
    action = "REORDER"      # Immediate action required
elif risk == "MEDIUM":
    action = "MONITOR"      # Watch closely, prepare to reorder
else:
    action = "NO_ACTION"    # Sufficient stock
```

## Output

The decision engine produces a comprehensive decision table with:

| Column | Description |
|--------|-------------|
| `store_id` | Store identifier |
| `product_id` | Product identifier |
| `current_stock` | Current inventory level (units) |
| `predicted_daily_demand` | Predicted demand per day (units) |
| `stock_out_risk` | Risk level: HIGH / MEDIUM / LOW |
| `recommended_reorder_quantity` | Suggested reorder amount (units) |
| `action` | Decision: REORDER / MONITOR / NO_ACTION |

## Usage

### Prerequisites
1. Ensure the Random Forest model is trained:
   ```bash
   python spark_jobs/demand_prediction_rf.py
   ```

2. Ensure streaming aggregation job has generated data:
   ```bash
   # Terminal 1: Start data producer
   python data_stream/sales_stream.py
   
   # Terminal 2: Start streaming aggregation
   python spark_jobs/retail_streaming_aggregation.py
   ```

3. Prepare current inventory data:
   - Update `data/current_inventory.csv` with latest inventory levels
   - Ensure columns: `store_id`, `product_id`, `current_stock`, `lead_time_days`

### Run the Decision Engine
```bash
python spark_jobs/inventory_decision_engine.py
```

## Model Characteristics

- **Algorithm**: Random Forest Regression
- **Features**: 4 numeric features (units_sold, revenue, units_per_minute, transaction_count)
- **Prediction**: Demand per 5-minute window
- **Time Conversion**: 5-min → daily (×288)
- **Deterministic**: Fixed seed (42) ensures reproducibility
- **Explainable**: Feature importance available from model

## Performance Considerations

- **Scalability**: Uses Spark for distributed processing
- **Efficiency**: Partitioned data reading for large datasets
- **Memory**: Configurable shuffle partitions (default: 4)
- **Latency**: Typical execution: 30-60 seconds for 50-100 product-store combinations

## Troubleshooting

### Error: "No such file or directory: retail_aggregations"
**Solution**: Run streaming aggregation job first to generate demand features

### Error: "Model not found: demand_rf_model"
**Solution**: Train the model using `demand_prediction_rf.py`

### Error: "current_inventory.csv not found"
**Solution**: Create inventory CSV with required columns

### Warning: "No records after join"
**Solution**: Ensure inventory CSV contains store/product combinations that exist in aggregations
